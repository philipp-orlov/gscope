# gscope frontend

An Angular + Angular Material dashboard for [../backend](../backend). Live
data from one [librpc](../../librpc) call, `Monitor.Watch`, on the WebSocket
route `/rpc`; no polling, no JSON.

## Setup

The charts, the process and temperature grids and the size pipe come from the shared web-ui-kit
(`../../web-ui-kit`: `@web-ui-kit/core` and `@web-ui-kit/angular`, `file:` dependencies). Build it first,
and run `npm run kit` here after every rebuild of the kit (`.npmrc` sets `install-links`, so npm copies
it in; `npm run kit` removes the old copy first, since npm does not replace a copy of the same version).
Fonts and icons (Roboto, Material Icons) are bundled from npm, so the dashboard needs no internet access.

```sh
(cd ../../web-ui-kit/angular && npm install && npm run build)
npm install
```

## Development

```sh
npm start   # ng serve --proxy-config proxy.conf.json (wired in angular.json)
```

Serves on http://localhost:4200 and proxies the `/rpc` WebSocket to the
backend on `http://localhost:8081` (see `proxy.conf.json`) -- start the
backend separately (`../backend/README.md`).

## Testing

```sh
npm test    # ng test -- vitest, jsdom, no browser/Chromium install needed
```

## Production build

```sh
npm run build
```

Output goes to `dist/frontend/browser/`. Point the backend at it directly:
```sh
./gscope-daemon --public-dir frontend/dist/frontend/browser
```

## The wire code

`src/app/core/wire/` and `src/app/core/librpc/` are generated and vendored, not
written by hand. After a change to `monitor.bufs` (or to librpc's TypeScript
runtime), regenerate them with the `rpcc` of a build tree:

```sh
node scripts/vendor-librpc.mjs ../../build/gscope/librpc/rpcc
```

`ctest -R gscope_frontend_wire_up_to_date` fails while they are stale.

## Structure

```
src/app/
  models/metrics.model.ts       The dashboard's Sample, SystemInfo
  core/
    wire/monitor.bufs.ts        Generated by rpcc from backend/include/gscope/wire/monitor.bufs
    librpc/                     librpc's TypeScript runtime (and libbufs'), vendored
    monitor-connection.ts       One Monitor.Watch call (RpcClient); MONITOR_CONNECT is the test seam
    metrics-decoder.ts          Wire updates -> Sample objects (fixed point, the inventory's names)
    metrics.service.ts          Owns the call, history buffer, reconnect/backoff, build-id reload
  dashboard/                    The page: CPU/memory/per-GPU cards + temperature chips
```

## Notes

- **Lightweight charts.** `ui-sparkline-chart` (from the web-ui-kit) redraws
  only when its inputs change or it is resized, never on a timer, so an idle
  tab costs nothing between updates. Its geometry (`computePoints()`,
  `drawSparkline()`) lives in `@web-ui-kit/core/charts` and is tested there.
- **More than one GPU.** The dashboard renders one card (and one chart) per
  entry in the latest sample's `gpus` array -- nothing is hardcoded to a
  single device.
- **Auto-updates on redeploy.** `MetricsService` remembers the `build_id` of
  the first inventory and calls `location.reload()` the moment a later one
  carries a different value (see backend/README.md's "Wire protocol").
  A redeployed frontend build reaches every open tab without anyone hitting
  refresh.
- **No `@angular/animations`.** Material 3's theming here is CSS-driven and
  the package is deprecated upstream in favor of `animate.enter`/`leave`;
  pulling it in would only add weight.
